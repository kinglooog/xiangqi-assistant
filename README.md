# 象棋接管助手

一个支持**半途接管对局**与**人机对战**的中国象棋软件：

- **人机对战**：选择执红/黑，摆好局面（默认开局或导入截图）后点「开始对战」，
  引擎直接替对方走子，你在棋盘上点击或拖拽走子即可对弈。
- **半途接管**：上传/粘贴一张 JJ 象棋（或天天象棋等）对局截图，软件自动识别并
  复刻棋盘，由 **Pikafish**（开源 NNUE 引擎，棋力远超人类特级大师，约 3200+ Elo）
  持续分析，实时高亮我方最佳着法与胜率。对手走子后在复刻棋盘上记录，照着在
  JJ 上走即可。

> 接管模式只做"识别 + 分析 + 建议着法"，不自动操作任何对局平台，手机版 / 电脑版截图均可用。

## 安装

需要 Python 3.10+（本项目用 `py -3.12` 创建了 `.venv`）。

```bat
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\pip install py7zr          # 仅下载引擎时需要
```

### 棋子检测模型（截图识别用，必需）

```bat
.venv\Scripts\python tools\download_models.py
```

从 [VinXiangQi](https://github.com/Vincentzyx/VinXiangQi) 的 Release 中解出
三个预训练 ONNX 模型到 `models/`（当前仓库已内置，无需重复下载）。
默认使用「中模型」，可在设置里切换。

### 引擎（Pikafish）

```bat
.venv\Scripts\python tools\download_engine.py
```

会自动从 [Pikafish Releases](https://github.com/official-pikafish/Pikafish/releases)
下载最新版并把 `Pikafish-Windows-x86-64-universal.exe` 与 `pikafish.nnue`
解压到 `engine\bin\`（当前仓库已内置，无需重复下载）。

验证引擎：

```bat
.venv\Scripts\python tools\engine_selftest.py
```

## 人机对战（直接对弈）

1. **启动**：`.venv\Scripts\python main.py`
2. 右侧模式选「**人机对战**」，选择你执**红方**或**黑方**。
3. 摆好棋盘：默认开局直接可下；自定义局面可先「导入截图」或手动摆子
   （摆子阶段双方棋子都可移动，例如点黑方棋子再点目标格）。
4. 点「**开始对战**」：若轮到引擎先行，它会自动走子。轮到你时点击棋子
   （选中后高亮可走点）再点击目标格，或直接拖拽。
5. 结束点「结束对战」回到摆子/分析状态；对战中被将死/困毙会自动收尾。

## 设置局面的两种方式

### 方式一：手动摆局（推荐，永远可用）

点「**手动摆局**」→ 在左侧调色板点选棋子 → 点击棋盘落子。
支持「移动」工具拖动已有棋子、右键快速擦除、「设为开局」一键初始化。
摆一个中局约 20 秒，**不依赖任何图像识别，任何棋子皮肤都可用**。

摆好后可直接「开始对战」，或继续用截图识别。

### 方式二：导入截图（YOLOv5 检测模型自动识别）

**三种载入截图的方式**（任选其一）：

1. **直接拖拽**：把截图文件从资源管理器**拖到软件窗口上**（主窗口或导入对话框都可以），
   松开即自动导入；从截图工具直接拖图片数据也可以。
2. **粘贴**：截图后按 `Ctrl+V`。支持剪贴板里的图片数据，也支持从资源管理器
   复制的图片文件；打开导入对话框时会自动尝试粘贴剪贴板内容，省一步操作。
3. **打开文件**：点「打开图片…」选择文件（支持中文/空格路径）。

载入后软件会：

1. 用 YOLOv5 检测模型识别棋盘与全部棋子，自动算出棋盘区域和每颗棋子的格子坐标；
2. 自动判断方向（你执黑时截图红方在上，会自动校正）；
3. 把识别结果填入右侧复刻棋盘（按截图同一方向显示，便于逐子对照）。

**校对**：识别错的棋子用下方调色板点选后点击该格修正（右键擦除）。
提示栏会显示识别出多少子、有无同格冲突或低置信度项，重点核对这些区域。

自动识别失败时（模型缺失、或该皮肤识别不出来），可点「手动校准四角」
依次点击棋盘左上/右上/右下/左下四个角交点，或直接改用手动摆局。

### 皮肤模板自校准（解决换皮肤后的识别混淆）

检测模型主要在天天象棋风格的棋子上训练。换用其它皮肤（如 JJ 象棋的部分
棋子主题）后，可能出现**系统性误判**（典型如 車→象、車→炮）。
对此软件提供"皮肤模板自校准"，无需任何训练：

1. **校准**：第一次导入该皮肤的截图时，像平常一样核对/修正识别结果，
   点 OK——软件自动按这个（经你确认的）局面采集该皮肤各类棋子的
   模板，存到 `models/skin_templates.npz`。你的人工修正就是准确标签。
2. **校验**：之后的每次识别，每个检出棋子都会与皮肤模板比对；
   模型判错且模板意见清晰时自动纠正，被纠正的格子会以**橙色圆圈**
   标注并提示复核。JJ 手机截图实测：易混淆的小模型错误 4 → 1，
   中模型零误报。
3. **安全**：模板意见不清晰（相关度低、前两名接近）时不干预；
   换回其它皮肤时旧模板不会乱改识别（跨皮肤实测零干预）。

模板随使用不断更新（每类保留最近 6 张）。若要重置，删除
`models/skin_templates.npz` 即可。

### 识别实测精度

在真实截图上实测（测试固件见 `samples/`，随仓库提供，均经逐子人工核对确认）：

| 测试图 | 尺寸 | 识别结果 | 耗时 |
|--------|------|---------|------|
| jj_endgame_mobile | 1240×2772 | **30 子，0 冲突，逐子核对全对** | 356 ms |
| image-20220711145348990 | 448×435 | **32 子，0 冲突，逐子核对全对** | 51 ms |
| image-20220711145437807 | 347×358 | **32 子，0 冲突，逐子核对全对** | 50 ms |

其中 `jj_endgame_mobile` 是 **JJ象棋 手机竖屏截图**：3D 立体青铜棋子皮肤，
棋盘上下还有大量 UI（头像、装饰物、按钮），仍被完全正确识别——
这类皮肤是模板匹配方案完全无法处理的。

三个模型实测对比（同一张 JJ 手机截图）：

| 模型 | 结果 |
|------|------|
| 中模型（默认） | 30 子，0 冲突，完全正确 |
| 万能带旋转 | 29 子，1 冲突，正确 |
| 小模型 | 30 子，但部分棋子类别出错（更快、精度略低） |

棋盘定位框与 90 个交点精确对齐（见 `tools/diagnose_recognition.py` 的
`02_detections.png`）。识别结果还会做局面合法性校验，非法局面会被拦下提示。

### 识别失败时怎么反馈

```bat
.venv\Scripts\python tools\diagnose_recognition.py 你的截图.png 输出目录
```

生成 3 个诊断文件：`01_source.png`（原图）、`02_detections.png`
（棋盘框 + 每个检测框与类别置信度叠加）、`03_result.txt`（FEN 与统计）。
看 `02` 即可判断是定位问题还是类别识别问题。

## 半途接管流程（JJ 象棋辅助）

1. 点「导入截图」或直接 `Ctrl+V` 粘贴对局截图（详见上文「设置局面的两种方式」）。
   识别不准时用调色板修正，或直接用「手动摆局」。
2. **设定阵营**：选择我方执红/黑、当前轮到谁，点 OK。
3. **接管开始**：引擎持续分析，轮到我方时棋盘上出现橙色箭头（起点→终点），
   状态栏显示中文着法（如"炮二平五"）与评估/胜率，照着在 JJ 上走子。
4. **对手走子后**：在复刻棋盘上把对方棋子拖到目标位置（或点击选子再点击落点），
   软件自动记录并重新分析。
5. 其他：`悔棋` 回退记录错误的一步；`翻转视角` 切换棋盘方向；
   `引擎设置` 调线程数、置换表、MultiPV、深度与用时。

## 界面说明

- 棋盘上下沿有双方纵线坐标：红方一侧中文数字（一~九，红方右手起为一），
  黑方一侧阿拉伯数字（1~9），翻转视角时坐标随之交换，方便对照中文着法。
- 走子支持两种方式：**点击选子 → 点击目标格**，或直接**拖拽**；非法着法会被
  拒绝并提示。
- **走子动画**：任何一方走子时，棋子会从起点滑动到终点（约 0.3 秒），
  起点留淡蓝色渐隐残影、终点有橙色落点圈，动画结束后保留上一步的绿色高亮。
  这是为了让你一眼看清**对方刚走了哪一步**。
- **音效与人声**：
  - 抬子/落子/吃子：lichess.org 开源仓库的**木质棋子实录音**（真实、清脆）；
  - 将军：落子音升调的清脆提示 + 神经语音喊"将军"；
  - 绝杀/困毙：低沉轰鸣垫底 + 神经语音喊"绝杀"/"困毙"；
  - 语音由微软 Edge 神经语音（zh-CN-YunjianNeural）**预生成随包分发**，
    运行时无需联网，自然度远高于系统 TTS；素材见 `assets/sounds/`，
    可用 `tools/gen_audio_assets.py` 重新生成。可在「引擎设置」里关闭音效/语音。
- **绝杀特效**：一方被将死/困毙时，全盘压暗、输方帅(将)位置扩散红色光环、
  屏幕中央弹出"绝杀"大字与结果说明，同时播放音效与人声。普通将军则弹出
  短促的"将军"提示。特效与动画按真实时钟计时，引擎高负载搜索时也不会
  卡顿拖长；引擎进程以低于正常的优先级运行，搜索时界面依然流畅。

### 拟人化鼠标（默认开启）

代点时不瞬移光标，而是按**真人操作特征**移动，可在「引擎设置」里调整：

| 特征 | 实现 |
|------|------|
| 轨迹形状 | 不是直线，是带弧度的曲线（垂直方向正弦偏置） |
| 速度曲线 | 最小急动度位置曲线 `10t³-15t⁴+6t⁵`：起步加速、中途最快、临近减速 |
| 时长 | 按**菲茨定律**（距离/目标大小），越远越慢；速度档再缩放 |
| 手部微颤 | 路径上 0.9 像素高斯噪声 |
| 事件频率 | 约 90 Hz 分步发送**相对移动事件**（真实输入流，非直接改坐标） |
| 停顿时序 | 到位后悬停 50~150ms → 按下 → 按住 60~130ms → 抬起 |
| 落点偏移 | 瞄准棋子中心 ±8% 格宽 |

- **两种轨迹算法**（设置里切换）：`最小急动度`（平滑、少过冲，默认）
  与 `WindMouse` 物理模拟（重力+风扰+摩擦，弧线与过冲回修更明显）；
- **速度档**：快 / 中 / 慢 —— 一步棋（两次点击）约 1.3s / 1.9s / 2.6s；
- 关闭拟人化则回到瞬时定位（旧行为），便于对比；
- 每次点击前的前台校验、落点窗口校验**不变**（安全保证不受影响）。

## 引擎分析面板怎么读（红黑不会搞混）

- **评估条**：左端标「红」、右端标「黑」，红色填充长度 = 红方胜率。
- **评估文字**用一种固定视角——**红方视角**，并显式写出谁领先：
  `红方领先 0.35` / `黑方领先 1.20` / `双方均势`；
  出现杀棋时显示 `红方 3 步内取胜`。
- **胜率**同时给出双方：`红方胜率 52% · 黑方胜率 48%`。
- **我方结论**一行直接翻译成你的处境：
  `你执红方：你领先 0.35` / `你执黑方：你落后 1.20` / `你即将被将死`。
- **当前轮到**明确写出是哪一方走子。
- **候选着法**每条都标出属于哪一方，例如
  `1. [红方] 红方领先 0.21  马八进七 马2进3 兵七进一 …`。
- **着法记录**按回合列出并标红黑：`1.  红 炮二平五   黑 马8进7`。

> 实现上，引擎给出的分数是「行棋方视角」，面板一律换算为红方视角显示；
> 并且每条分析信息都绑定到"被搜索的那个局面"，局面一变立即丢弃旧数据，
> 避免上一步的评估串到当前局面把红黑显示反。

## 开局走法（可选）

接管时可在「开局走法」下拉中指定开局，软件在轮到我方时**优先按开局行棋**，
走完（或该着法在当前局面不可行）后自动恢复由引擎选最优：

| 开局 | 着法 |
|------|------|
| 中炮（当头炮） | 炮二平五 |
| 过宫炮 | 炮二平六 |
| 士角炮 | 炮二平四 |
| 巡河炮 | 炮二进二 |
| 起马局 | 马二进三 |
| 飞相局 | 相三进五 |
| 仙人指路 | 兵七进一 |
| 双铁滑车 | 车一进一、车九进一 |
| 御驾亲征 | 帅五进一 |
| 默认 | 引擎选最优 |

- **执黑时自动镜像**（如 炮二平五 → 炮8平5），红黑通用；
- **每局重新应用**——配合自动续局，连下的每一局都按此开局；
- 更换下拉选项立即生效；选择会记入配置，下次启动保留；
- 停止接管后不再干预（手动对局/观战不受影响）。
- 开局着法**仅在我方回合**执行（引擎在对手回合也会分析给出着法，
  若不加区分会把开局着法判为不可行而跳过——双铁滑车曾只走一边的車）；
- 开局着法**只在开局阶段生效**（局面与标准开局相差不超过 3 步）——
  中局接管时套用开局等于白送一步（实际发生过，评估直接掉到 -7.6）。

## 一键接管（推荐用法）

右侧最上方的大按钮「**🎯 一键接管对局**」——一个按钮全自动：

1. MuMu 里进入 JJ 对局（随便哪方、任何局面），点按钮；
2. 只选一件事：**我执红/黑 + 现在轮到谁**（四个选项任选其一）；
3. 软件自动完成剩下的全部：扫描窗口找到含棋盘的那个 → 置顶 →
   识别局面 → 自动同步双方着法 → 轮到你时**自动在对局窗口落子**。

你只需要看着它下。再点一次按钮即停止（同时取消置顶）。

防误选机制：自动找窗口时，识别结果必须通过"合理性校验"
（棋盘框比例正常、双方将帅在九宫、子力合法——排除把别的窗口
内容误认成棋盘的情况），且连续两帧一致才采纳；窗口按进程 PID
排除软件自身。接管后对局窗口自动置顶并拉到前台（停止时取消）。

排查：接管结果异常时看 `~/xq_assistant_takeover.log`——记录了每个
候选窗口的探测结论（识别子数、采纳/排除原因），并排除系统进程窗口
（输入体验/设置等透明或系统层，防止把它们误认成棋盘窗口置顶）。

## 对局窗口同步（一期·自动观察）

把软件连到对局窗口（MuMu 模拟器里的 JJ 象棋、或任何含棋盘的窗口），
之后**双方着法自动同步**进复刻棋盘——接管模式不再需要手动拖拽记录：

1. 照常「导入截图」（或手动摆局）设置当前局面与我方执子；
2. 右侧「对局窗口同步」点「刷新」→ 选中 JJ 对局所在窗口 →「开始观察」；
3. 软件每 0.7 秒抓一次窗口画面，连续两帧识别一致才认定稳定。
   着法判定用**转移约束推断**：从当前局面的合法走法（通常四十来种）
   中选出最能解释观察帧的那一种——棋子"在哪/什么颜色"远比"是什么字"
   可靠，因此你皮肤上的 車↔象/炮 类误读会被自动容错。

异常处理（全自动自愈，无需手动干预）：

- **卡死自愈（多层保险）**：
  - 重同步时优先用"谁的一步合法着法能解释这次变化"判定走子方（比棋子颜色可靠）；
  - 无法解释时按场景保守偏向我方，绝不无限等待；
  - 我方回合超过 6 秒无动作时看门狗自动重新触发分析；
  - 同一着法的重复点击拦截只保留 6 秒（防"点击静默失败却永久拦住"）；
  - **引擎健康检查**：进程退出立即重启并重新分析；搜索超 15 秒无 bestmove
    （引擎挂死）同样重启救援——旧逻辑对"搜索在飞"只刷新计时，会永远卡在等待分析；
  - **单格差异先排除检测漏检**：低阈值复核该格，棋子仍在则判定漏检、保持本地
    棋盘（否则会把漏检当成真丢子，本地少一子、引擎误判局势）；
  - **点击前一致性校验**：若窗口局面已变化（对手刚走子、尚未同步）则放弃
  本次代点，先同步再重新分析——否则会"按旧坐标点新局面"而走出漏招；
- **漏招审计**：我方走子后评估骤降超过 1.5 兵时告警（附带局面指纹），
  便于及时发现"引擎分析的局面与真实不符"；每次代点日志都会记录局面 FEN；
- **误判"对局结束"自愈**：本地若误判结束会导致同步与分析全部停摆
  （静默卡死），当窗口局面与之明显不同时自动清除该判定并重新同步；
- **静默自诊断**：超过 15 秒无任何事件时记录完整状态（轮次/我方/分析中/
  引擎存活/帧子数），停滞原因一目了然；
- 非法局面（子力超量、将帅照面/出九宫、兵卒停在己方底线、
    **非行棋方被将军**）一律拒绝送引擎——Pikafish 遇到非法局面会直接退出
    （实测：连续 152 次"退出→重启→再退出"死循环就是这个原因）；
  - **轮次按将军关系自动纠正**：若"非行棋方正被将军"，说明轮到谁猜错了，
    被将军的一方必然是走棋方，软件自动翻转轮次（比拒绝更彻底）；
  - **引擎死亡循环护栏**：同一局面若已杀死过引擎，不再重复送分析，
    而是提示你修正局面；
- **检测抖动防护**：识别偶发漏检会让棋子"凭空消失"，多格路径同样先做
  低阈值复核——能找回就按复核结果解释走子，绝不采纳抖动画面；
- **帧质量阶梯**：标准阈值 → 低阈值复核 → 判定"棋盘不可用"（允许续局介入
  并给出提示），连续 30 帧异常还会把画面存档到 `~/xq_sync_fail.png` 便于诊断
  （避免此前"连续丢帧 562 次、几分钟静默无动作"的情况）。

- **着法不合法 / 画面变化无法解释**（识别偏差、弹窗遮挡后跳变）：
  **自动以 JJ 窗口局面为准重新同步**——JJ 是真实对局，永远是准的，
  本地只是镜像；限频 15 秒防循环；
- **窗口最小化**：暂停同步，恢复后自动继续；
- 棋盘消失（弹窗盖住）自动暂停，重现后自动恢复；
- 全过程写入 `~/xq_assistant_takeover.log`（[同步] 前缀为同步事件：
  每步着法、每次自愈、识别异常），出问题看它。

### 自动代点（二期·已完成）

勾选「**自动代点**」（需先开始观察）后进入全自动模式：

- 轮到我方时，引擎算出着法后**直接在对局窗口点击落子**
  （起点、终点两次真实鼠标点击，坐标按识别到的棋盘框换算，
  带随机偏移与拟人化延迟，落子节奏用「对战模式每步用时」控制）；
- 我方着法是否成功**以窗口画面回读为准**——不本地臆测，
  落子后 8 秒未见画面变化会提醒手动检查；
- 同步确认的着法自动记录、播报，随后引擎继续思考下一回合；
- 人机对战模式 + 窗口观察 + 自动代点 = 挂机自动下棋；
  接管分析模式 + 自动代点 = 你看它下。

**自动续局**（勾选后生效）：一局结束后软件自动完成"关闭结算弹窗 →
点「再来一局」→ 识别新开局"，并按"你的棋子在下方"的惯例**重新判定阵营**：
你执红就先行，你执黑就等对方——不受上一局设定的影响。

定位方式（三级，越靠前越优先）：

1. **模板匹配**（以**棋盘框锚定尺寸**，适配任意分辨率/模拟器工具栏——
   按窗口宽度估算会错，因为窗口含黑边与工具栏）；
2. **坐标兜底**：模板未命中时，按"按钮相对**画面**的固定位置"换算坐标直接点击
   ——标定自两张真实结算截图（棋盘大小不同、按钮位置几乎相同），
   证明按钮锚定在应用界面底部（横向居中、距底约 6.7%），与棋盘大小无关，
   换算误差 ≤15 像素（按钮宽约 200 像素）；
3. 触发方式：**每帧都检查按钮**（约 1.4 秒一次）——「再来一局」按钮的存在
   本身就是结算界面的最可靠标志，不依赖"对局已结束"（对手认输时本地判不出）
   或"棋盘读不到"（结算界面棋盘往往完整可见）；
4. **结算界面可直接接管**：在结算界面点「一键接管」也能连上——此时棋盘被
   结算弹窗遮挡、棋子不全、将帅可能被挡，合理性校验必然失败，但只要画面里
   有「再来一局」就接受该窗口（跳过阵营选择与局面核对），直接自动开下一局。

多层安全约束（X 字形模板过于通用，必须严防误点应用自身的关闭按钮）：

- **优先直接点「再来一局」**（绿底四字特征鲜明、只在结算界面出现），
  能看到它就从不点叉；
- 只在「再来一局」被弹窗挡住时才尝试关弹窗，且必须同时满足：
  对局已结束 + 棋盘确实读不到（弹窗遮挡）+ 叉位于画面**中部安全区域**
  （四周边缘是窗口/应用自身按钮的位置，被硬性排除）+ 每次结算最多点 3 次；
- 所有点击前做**落点窗口校验**：该屏幕坐标处最顶层的窗口必须是接管窗口
  （这是防点错窗口的真正保证；窗口前台化改为"尽力而为"，
  因为 Windows 前台锁会拒绝非前台进程的抢焦点请求）。

安全阀：取消勾选立即停手；弹窗遮挡/识别不稳时同步自动暂停，不会盲点。
支持你**手动在 JJ 里走子**——软件会识别并跟随任何人走的任何步
（重同步的轮次从"哪颗子移动了"自动推断），人机协作下棋也行。

## 超强算力设置（默认）


| 选项 | 默认 | 说明 |
|------|------|------|
| 思考线程数 | CPU 逻辑核数-1 | 多线程搜索 |
| 置换表 | 1024 MB | 越大越强 |
| 深度上限 | 24 | 两种模式共同的深度封顶 |
| 分析模式每步用时 | 0（不限） | >0 时按固定时间思考 |
| 对战模式每步用时 | 3000 ms | 每步用时上限，时间到即出招 |

配置保存在 `~/.xq_assistant.json`。线程/置换表修改后需重启软件。

### 速度与棋力

搜索一律采用**「用时上限 + 深度封顶」双限制**：深度上限与纯深度搜索相同，
时间到只是提前结束，**不会降低棋力上限**。实测（15 线程、1024MB 置换表）：

| 局面 | 双限制 3s 给出的着法 | 纯 depth 24 给出的着法 | 纯 depth 24 耗时 |
|------|---------------------|----------------------|-----------------|
| 开局 | b2e2 | b2e2 | 4.8s |
| 中局（复杂） | b6b9 | b6b9 | 10.6s |
| 中局（复杂） | c2d4 | c2d4 | 9.1s |

复杂局面下响应快 2~3 倍，**着法与算满深度时完全一致（5/5）**。
可用 `tools/bench_strength.py` 自行复现该验证。

另外两处与棋力无关的提速：

- **分析模式实时建议**：箭头直接由引擎 info 流的 PV 首着驱动，
  实测 **0.27~0.5 秒**即出现建议（原先要等整轮搜索完成，复杂局面需 14 秒），
  之后随深度增加持续修正，最终仍以完整搜索结果为准。
- **减少引擎线程与 GUI 的争用**：info 行按 60ms 节流转发，PV 的中文记法
  只在实际转发时翻译（原先每条 info 行都翻译），GUI 刷新开销大幅下降。

## 常见问题

- **截图识别不准 / 认不出棋子**：先用 `tools/diagnose_recognition.py` 看
  `02_detections.png` 判断是定位问题还是类别问题；可在「引擎设置」里换
  「万能带旋转」模型试试；仍不行就用「手动摆局」（最可靠，任何皮肤可用）。
- **导入后棋盘整体错位**：多为方向问题，勾选/取消「截图红方在上」即可校正；
  软件一般会自动判断（你执黑时截图红方在上）。
- **提示"局面不合法"**：识别校对失误或摆错（子力超量、将帅缺失、将帅照面）。
  对话框和状态栏会给出具体原因，修正后即可。
- **引擎未启动**：确认 `engine/bin/` 下有 exe 与 `pikafish.nnue`；无引擎时识别、
  摆局与记录功能仍可用，人机对战不可用。
- **程序出错时**：不会再无声闪退——会弹出错误提示，并把完整堆栈写入
  `~/xq_assistant_error.log`，便于排查。
